Pi showed `$ git status` (or `$ git status (timeout 10s)`).
3. **Host-version rule.** The runbook as published still said a changed host version means E1b runs again. The owner decided on 2026-11-14 that a drill is accepted for the tested host versions and later, and that a later version is recorded and not a stop (`E1B-RUNBOOK.md`, "Host versions"; the change is a separate runbook PR that merges before this record). The drill ran under the earlier rule until E.4, and under the new one after. **The only later version seen in `drill2` is Claude Code 2.1.326 at the end of F.6**; Pi stayed at 1.5.0. The Linux E1a account ran Claude Code 2.1.325 and Pi 1.5.2 (`0.1.2.md`). The limit of this: nothing detects a host-caused break in update or rollback until the next drill or a user report.
4. **The first promote run failed, and was replaced by a fresh dispatch.** Run `43557924380` (dispatched 2026-11-14 04:41:50Z, approved 2026-11-15 01:11:54Z) failed at its first step: `actions/create-github-app-token` returned 401 "A JSON web token could not be decoded" because GitHub could not decode the JSON web token made from the `PROMOTE_APP_PRIVATE_KEY` environment secret (stored 2026-11-13, never changed before the failure). The candidate App's key, used by `release.yml`, worked throughout, so the fault was in the stored promote key; the exact defect in it was not examined. No promotion work ran; `release` stayed at `f8589d5…`. V7 (the approval requirement) had passed on that run: the failure was a defect in the key, found only at promotion time. The run was then re-run once, by the other maintainer (attempt 2, 2026-11-16 18:42), and failed the same way; **the runbook says a failed promotion is replaced by a fresh dispatch, not re-run**. The owner accepted that limit of "Prevent self-review" earlier (`MAINTAINER-SETUP.md`, owner decision 2026-11-12), and the failed re-run did nothing, so no note beyond this one was written. After the owner generated a new key for the release App, stored it as the `promote` environment secret and deleted the old key, a fresh dispatch (`43945512214`, 2026-11-16 20:01:58Z, approved ~21:25:17Z) succeeded: `release` moved `f8589d5… → b72867f…`, `promoted-v0.1.2` was created, and `v0.1.2` was marked latest.
